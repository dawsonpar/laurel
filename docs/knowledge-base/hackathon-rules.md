# Hackathon Rules and Judging

**Source:** [Devpost](https://vibecodeforgoldwithgoogle.devpost.com/)
**Last reviewed:** 2026-04-28

## Hard requirements

- US residents only, age of majority
- Must use Gemini API
- Must deploy on Google Cloud (Cloud Run, App Engine, or AI Studio)
- Public code repository under Apache License 2.0
- Hosted project URL judges can test
- Text description with features, technologies, data sources
- 3-minute video demo, unlisted on YouTube, English with subtitles
  - Must show live demo
  - Must display Google Cloud console/code usage

## Submission deadline

**2026-05-11 5:00pm PDT.** No extensions stated.

## Five challenge tracks

1. Performance Parity Report
2. Hometown Success Engine
3. Road to LA28 Games Bracket
4. Athlete Archetype Agent
5. **Choose Your Own Challenge** (Laurel's track)

## Judging criteria

| Weight | Criterion |
|---|---|
| 40% | **Impact** (fan-centric questions, Paralympic representation, inspirational vision) |
| 30% | **Technical Depth & Execution** (functionality, Gemini integration, GCP usage) |
| 30% | **Presentation Quality** (demo storytelling, UX clarity, content compliance) |

Paralympic representation being part of Impact (40%) is why Laurel structurally weights Olympic and Paralympic content equally (3:3 sport count).

## Hard content rules

- Conditional phrasing only ("could help find"), not guarantees
- Avoid implying geography guarantees athletic results
- Respect NIL (Name, Image, Likeness) restrictions on athletes
- No identifying specific private individuals in datasets
- Focus on AI's analytical capabilities (insights, patterns) rather than performance promises
